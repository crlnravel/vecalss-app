## Design Specificity Verdict

The shared layer is recognizably Vecalss: Voyage greens, sea-glass surfaces, warm-sun actions, rounded controls, mascot-led learning language, and the extracted reference dashboard primitives. It is not yet one coherent product experience at the route level. The consuming code currently presents at least three visual worlds: green operational workspace, cyan/lime/slate onboarding, and cream/black editorial marketing. That can be a deliberate product architecture, but it is not documented as a tiered design system and therefore reads as drift.

Assessment B's deterministic scan found no anti-pattern records: 57 scannable `.ts`/`.tsx` files, exit code 0, output `[]`, zero primary/advisory findings, and no rule locations. Its auxiliary static color scan reports 33 raw color-function/hex lines across 16 files (25 function matches and 9 hex matches; categories may overlap). Most shared-layer matches are intentional token-equivalent shadows or gradients, but the manual review still found route-level palette and contract inconsistencies that the detector cannot infer.

## Overall Impression

The component foundation is better than the route-level consistency. `ReferenceSurface`, `ReferenceSelect`, `ReferenceEmptyState`, semantic status badges, and the icon barrel establish a credible system. The biggest opportunity is to make those contracts enforceable at the boundaries so every Voyager, Kapten, and Admin surface feels like the same product.

## What's Working

- `components/dashboard/reference-dashboard-primitives.tsx:126-164` gives operational empty states a consistent icon/title/description/action structure, and `ReferenceSelect` plus `REFERENCE_CONTROL_CLASS_NAMES` centralise listbox geometry and focus treatment.
- Icon usage is disciplined: the detector review found 16 component files importing from `@/lib/icons`, with no Lucide, Heroicons, or standalone Phosphor imports under `components`.
- The documented compact-filter and full-width-line tab wrappers exist (`components/ui/compact-filter-tabs.tsx:27-46` and `components/ui/full-width-line-tabs.tsx:26-47`), while `Button` exposes named marketing, onboarding, learning, and reference families instead of only generic color variants.

## Priority Issues

### [P1] Onboarding is a separate brand system

**Evidence:** `modules/student/components/onboarding-form.tsx:31-49,59,84-100,159-185,197-254` uses cyan/lime SVGs, slate text and surfaces, cyan focus rings, yellow selection treatments, and bespoke gradients. Its native selects at `:229-238` bypass the shared listbox/select language.

**Why it matters:** First-time Voyager users meet the product at onboarding. The mascot and copy are warm, but the cyan/slate visual vocabulary makes the first impression feel like a different app and weakens recognition of the Voyage green system.

**Fix:** Decide whether onboarding is an intentional “first voyage” art direction. If not, replace route-local colors with named Voyage tokens, use the shared field/choice contracts, and route selects through a student-safe shared select wrapper. If yes, document the surface as a sanctioned variant and promote its colors/geometry into tokens instead of leaving them inline.

**Suggested command:** `$impeccable colorize modules/student/components/onboarding-form.tsx`

### [P1] Shared size contracts are advisory, not enforced

**Evidence:** `components/ui/input.tsx:12` defaults to `h-9` (36px) even though the design contract is 44px minimum. `components/ui/button-variants.ts:54,68-70` exposes `xs`/`icon-xs` at 24px and `icon-sm` at 40px. Operational examples include `components/ui/data-table.tsx:137` (`size-5` filter removal), `:468` (`size-7` search clear), and `:510-514` (36px action trigger). `AttachmentAction` defaults to `icon-xs` at `components/ui/attachment.tsx:145-158`; the onboarding back button is 40px at `modules/student/components/onboarding-form.tsx:165-169`.

**Why it matters:** The same “icon-only” pattern changes from a comfortable action to a 20–36px target depending on route. This creates accessibility risk for touch users and makes density feel accidental rather than intentional.

**Fix:** Make the default `Input`/icon-only contracts meet 44px, then add an explicitly named dense-table exception with a documented expanded hit area. Migrate clear/remove/action controls and remove local `size-7`/`size-8` overrides where they are interactive. Keep visual icons small inside a larger button box.

**Suggested command:** `$impeccable harden components/ui`

### [P1] Tabs have competing visual implementations

**Evidence:** The base tab list/trigger use `h-9` and `h-[calc(100%-1px)]` in `components/ui/tabs-variants.ts:3-10` and `components/ui/tabs.tsx:42-50`. `modules/dashboard/DashboardPageModule.tsx:419-429` recreates compact pills locally at `h-9`. `modules/vera-ai/VeraAiPageModule.tsx:4304-4338` recreates a line tab with rounded tops, active mint fill, and route-specific heights instead of the shared full-width wrapper.

**Why it matters:** Kapten and Admin users must relearn active state, height, and spacing across otherwise equivalent tab sets. The dashboard example also conflicts with the documented 44px interaction contract.

**Fix:** Use `CompactFilterTabs` for dashboard chapter filters and `FullWidthLineTabs` for Vera context tabs. Restrict raw `TabsList`/`TabsTrigger` styling to the two named variants, then enforce minimum trigger height in the base contract.

**Suggested command:** `$impeccable distill components/ui/tabs.tsx`

### [P1] Native selects bypass the operational control language

**Evidence:** Raw `<select>` elements remain in `modules/media/components/MediaLibraryModals.tsx:101`, `modules/mentor/KaptenQuestionBankCataloguePageModules.tsx:282,328,381`, `modules/admin/StudentDetailPageModule.tsx:292`, `modules/admin/components/create-kapten-form.tsx:76`, `modules/admin/imports/ImportsIntakeModule.tsx:223`, and the onboarding form at `modules/student/components/onboarding-form.tsx:229,235`. In contrast, `ReferenceSelect` and Base UI dropdown wrappers provide the canonical focus, arrow, radius, and popup behavior.

**Why it matters:** Daily operational routes expose different popup behavior, focus rings, arrows, and geometry for the same selection task. Native controls can be valid in a deliberate mobile-first surface, but these callsites are not marked as such.

**Fix:** Create or adopt one shared semantic select contract that supports the required native form submission behavior, migrate Admin/Kapten/Media operational callsites, and explicitly document any remaining native-select exception. Keep onboarding's palette decision separate from the select migration.

**Suggested command:** `$impeccable polish components/dashboard/reference-dashboard-controls.tsx`

### [P2] Operational status and table primitives still fork

**Evidence:** `modules/mentor/KaptenQuizResultsPageModule.tsx:82` uses the legacy generic `Badge` for operational “Terkirim/Sedang dikerjakan” statuses, while `StudentBadge`/`MentorBadge` are the semantic system used by reference surfaces. The generic badge is `rounded-md` and borderless (`components/ui/badge-variants.ts:3-17`); `MentorBadge` separately removes the canonical border and adds a bespoke shadow (`components/ui/mentor-badge.tsx:29-35`). The table primitive always wraps in `overflow-x-auto` and makes cells `whitespace-nowrap` by default (`components/ui/table.tsx:7-16,83-93`), while the operations guidance calls for overflow only when necessary and truncation for long values.

**Why it matters:** Status meaning and responsive behavior change between mentor/admin views. On narrow screens, long names and categories can force horizontal scanning instead of preserving the primary row action.

**Fix:** Reserve generic `Badge` for decorative marketing usage, migrate operational statuses to semantic `StudentBadge`/`MentorBadge` with one border contract, and make table overflow/nowrap opt-in per dense table. Add truncation and a consistent empty state to the shared table/data-table path.

**Suggested command:** `$impeccable audit components/ui`

## Cognitive Load

- The reference primitives reduce decisions by standardising surface, select, status, and empty-state patterns; keep that advantage.
- Route-level tabs, native selects, and status chips make equivalent decisions look different. The user has to remember presentation instead of focusing on the content task.
- Vera AI contains an outer workspace tab set and a second context tab set (`modules/vera-ai/VeraAiPageModule.tsx:726` and `:4304`), so a strong active-state contract matters more than decorative variation.
- Data-table search, filters, column visibility, selection actions, and row actions are a reasonable operational set, but tiny clear/remove controls increase interaction uncertainty.

## Emotional Journey

- **First touch:** Mascot, Indonesian copy, and the explicit “Lewati dulu” path make onboarding welcoming. The cyan/slate palette breaks the emotional handoff from the rest of Vecalss.
- **Daily work:** Reference surfaces, semantic statuses, and centered empty states can make Kapten/Admin work feel calm and trustworthy. Inconsistent popup and tab behavior introduces small but repeated friction.
- **High-stakes moments:** Quiz results and import/table states need a single status vocabulary so “Terkirim,” “Menunggu,” and error states feel equally authoritative.
- **End state:** The product has enough warmth and voyage metaphor to be memorable; the next improvement is continuity, not more decoration.

- The canonical reference shell is a strong baseline; the risk is inconsistent adoption rather than missing structure.
