## Overall Impression

The waiting room has a good instinct: make the countdown unmistakable, explain the exam contract, and require an explicit acknowledgement before entry. The failure is orientation. The page asks for a high-stakes commitment while hiding the assessment identity and keeping the most important state logic inside an unlabeled disabled button. Make the student’s context and next action explicit before adding more decoration.

## What’s Working

- The dark green hero makes the time window the visual anchor. The numerals are large, tabular, and paired with Jam / Menit / Detik; source color math shows comfortable contrast against the declared gradient.
- The four-rule acknowledgement flow is a credible pre-flight contract. The checkbox has a broad wrapped-label hit area, the button is 48px high, and the shared button variant supplies a visible focus ring.
- The consent gate and post-attempt branches are thoughtful: Start is blocked until acknowledgement/time-window eligibility, while in-progress and completed attempts get explicit Lanjutkan ujian / Lihat hasil states.

## Priority Issues

### [P1] The waiting room has no assessment identity or page-level heading

**Why it matters:** The non-attempt state never renders tryout.title; it presents only “Ruang tunggu”, the countdown, and “Sesi: …” (ParticipantWaitingRoomModule.tsx:112-139). The page also has no h1, while the mobile shell hides the breadcrumb. A Voyager with multiple invitations can land here without a reliable visual or screen-reader answer to which exam they are consenting to.

**Fix:** Put “Ruang tunggu · [Tryout title]” above the timer and add a compact metadata row for assignment/session name, CBT/CAT format, section count or total duration, and deadline. Keep “Ruang tunggu” as supporting context. Add route metadata for the specific tryout/session instead of inheriting the generic root title.

**Suggested command:** $impeccable clarify, then $impeccable layout

### [P1] The countdown semantics are ambiguous for a high-stakes session

**Why it matters:** Before opening, the label correctly says “Waktu sebelum tryout dimulai”; after opening, the same component says “Sisa waktu tryout” while counting down to availableUntil (ParticipantWaitingRoomModule.tsx:64-75). In the inspected fixture the number was about 152 hours, which can be mistaken for the exam duration rather than the availability deadline.

**Fix:** Separate “Tryout dibuka dalam …” from “Jendela pengerjaan berakhir dalam …”. Keep explicit Mulai and Batas akhir timestamps next to the timer, and render a deliberate closed state with a next action/back guidance instead of a zeroed timer.

**Suggested command:** $impeccable clarify

### [P1] Rules and acknowledgement are jargon-heavy and repetitive

**Why it matters:** CBT, CAT, autosave, and integritas require translation for a first-timer. The four multi-clause rule cards are then partially repeated by the long checkbox sentence (ParticipantWaitingRoomModule.tsx:38-43, 161-164), making the consent feel legalistic rather than confidence-building.

**Fix:** Use plain Indonesian at first mention: explain what CBT/CAT changes for the student, say why focus tracking exists, and reduce the checkbox to one concise acknowledgement. Keep secondary policy detail behind progressive disclosure while preserving the four-item maximum.

**Suggested command:** $impeccable clarify, then $impeccable distill

### [P2] Disabled Start gives no reason or actionable next step

**Why it matters:** canStart combines consent, opening/closing time, and assignment status (ParticipantWaitingRoomModule.tsx:64-70), but the button always says “Masuk ke ujian” (166-169). On the inspected mobile view, the muted disabled treatment looks like a decorative pill; students cannot tell whether to tick the checkbox, wait, or recover from an inactive/expired session.

**Fix:** Render state-specific helper copy: “Centang pernyataan di atas untuk melanjutkan”, “Tombol aktif saat [WIB]”, “Sesi sudah berakhir”, or a precise inactive/revoked message. Change the CTA label to match, announce the state, and keep a visible text link back to the detail page.

**Suggested command:** $impeccable clarify, then $impeccable audit

### [P2] Mobile orientation and action reach are too implicit

**Why it matters:** The four cards stack before the CTA, the shell hides breadcrumbs below md, and the waiting module begins with an icon-only back button (StudentWorkspaceShell.tsx:87-105; ParticipantWaitingRoomModule.tsx:113-121). On the 390px view, the student scrolls through a long policy block before reaching the right-aligned action; a reload also resets the acknowledgement state.

**Fix:** Keep the tryout title and deadline visible above the fold, render a labeled “Kembali ke [Tryout title]” link, shorten the rules into scan-friendly rows, and use a sticky bottom action only once the consent state is clear. Preserve or explicitly restore acknowledgement state when returning from an interruption if product policy allows it.

**Suggested command:** $impeccable adapt, then $impeccable layout

## Minor Observations

- Expand CBT and CAT in plain language at first mention.
- When expired, replace the terminal 00:00:00 display with a status panel so the page no longer resembles an active countdown.
- Add aria-busy or an equivalent status cue to the start transition alongside the visible “Menyiapkan…” text.
- A visible “Kembali ke detail tryout” label is more discoverable than the ChevronLeft icon and tooltip/title.
- The waiting route has no route-level metadata export, so the browser title can remain generic.
- The back affordance uses lucide-react while the content uses Phosphor; not harmful, but the mixed icon language is noticeable.

- The waiting room describes future autosave/status and fullscreen behavior but gives no small connection/fullscreen preflight cue.
