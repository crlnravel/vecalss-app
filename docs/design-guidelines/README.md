# Vecalss design-guidelines

This folder decomposes the root [DESIGN.md](../../DESIGN.md) into searchable,
task-sized guideline files. Start with the root for tokens and invariants, then
open only the focused file needed for the current surface.

| File | Use when |
| --- | --- |
| [foundations.md](foundations.md) | Colors, typography, layout, depth, shapes, and page titles |
| [components.md](components.md) | Buttons, chips, tabs, status tokens, cards, and inputs |
| [feedback.md](feedback.md) | Validation, error hierarchy, success feedback, and Sonner |
| [copywriting.md](copywriting.md) | Brand voice, terminology, and user-facing copy |
| [operations.md](operations.md) | Dropdowns, approved tables, overflow, and TanStack behavior |
| [navigation.md](navigation.md) | Parent back behavior, shell navigation, and Materi journey nodes |
| [principles.md](principles.md) | Cross-cutting Do/Don't rules and anti-patterns |

The root file remains the authority for machine-readable tokens. Focused files
hold the detailed application rules; do not invent a competing visual language
inside an individual route.
